# DRAB — ملف الإنتاج المشترك

**English:** Dr. Rajab Al-Barbar Medical Platform  
**الاختصار:** DRAB  
**الإصدار:** 0.1 — وثيقة تأسيسية  
**التاريخ:** 25 نوفمبر 2026  
**الحالة:** تأسيس وتخطيط — لم يبدأ التطوير البرمجي بعد

## 1. الغرض من الملف
هذه الوثيقة هي مرجع الإنتاج المشترك بين صاحب المشروع وفريق التنسيق ووكلاء الذكاء الاصطناعي الذين سيشاركون لاحقاُ من ChatGPT وClaude وZ.ai. تحفظ القرارات المعتمدة، وتفصلها عن المقترحات، وتحدد نطاق المنصة ومراحل العمل وقواعد التعاون.

## 2. الهوية والقرارات المعتمدة
- العلامة الرئيسية: **د. رجب البربار / Dr. Rajab Al-Barbar**.
- الاسم الرسمي: **منصة د. رجب البربار الطبية / Dr. Rajab Al-Barbar Medical Platform**.
- الاختصار: **DRAB**.
- المنصة طبية متعددة الأقسام، وعيادة القدم السكري هي الأساس الطبي والمحور الرئيسي.
- لا يُستخدم الصليب في الشعار أو الهوية.
- لا يُستخدم اللون التركوازي الطبي التقليدي.
- لوحة الألوان النهائية، والشعار، والخطوط، ونظام التصميم: **قرارات معلّقة لاعتماد صاحب المشروع**؛ الكحلي والذهبي اقتراح سابق وليس اعتماداُ نهائياُ.
- مبدأ التقنية: Open Source First، ملكية الكود والبيانات، قابلية نقل الاستضافة، والبدء بالخطط المجانية دون اشتراكات مدفوعة إلا بموافقة صريحة.
- لا يبدأ النشر أو الشراء أو تفعيل الاشتراكات دون موافقة صاحب المشروع.

## 3. نطاق المنصة
### أ. الواجهة العامة
- الصفحة الرئيسية والتعريف بالدكتور والمنصة.
- عيادة القدم السكري: الخدمات، المواقع، المواعيد، التوعية، الحالات التعليمية.
- مكتبة طبية متخصصة: الكتب، المقالات، الأبحاث، الإرشادات والمراجع.
- مجلة علمية إلكترونية شهرية تجمع وتفهرس الأبحاث المحلية والعربية والإسلامية والعالمية، مع تمييز واضح بين فهرسة الأبحاث المنشورة وبين استقبال أبحاث أصلية وتحكيمها.
- منتدى مرضى القدم السكري ومجتمع الدعم.
- متجر أصدقاء السكري وذوي الاحتياجات الخاصة والأشخاص ذوي المتلازمات.
- خدمات التمريض والرعاية المنزلية وطلبات الزيارات.
- استوديو إعلامي: برنامج ترفيهي توعوي مرتين أسبوعياُ.
- مسلسل أنيمي طبي تعليمي شامل، مستوحى من فكرة الرحلة داخل جسم الإنسان، مع تطوير بصري وسردي حديث.
### ب. المنظومة الداخلية
- لوحة تحكم مركزية.
- أرشيف المرضى والسجل الطبي الإلكتروني.
- إدارة الملفات والزيارات والتشخيصات والتحاليل والتقارير.
- متابعة الجروح والقرح بالصور والقياسات والتواريخ.
- المواعيد والإحالات والتمريض المنزلي.
- إدارة الفريق والمستخدمين والأدوار والصلاحيات.
- إدارة المكتبة والمجلة والمنتدى والمتجر.
- التقارير والإحصاءات وسجل التدقيق.
### ج. الذكاء الاصطناعي والأتمتة
- مساعد بحث للمصادر الطبية والعلمية.
- مساعدة تحريرية للمجلة والمكتبة مع توثيق المصادر.
- مساعدة إدارية للفرز والتلخيص وإعداد المسودات.
- تنبيهات ومهام متابعة بعد اعتماد الطبيب أو الموظف المختص.
- لا يصدر النظام تشخيصاُ أو قراراُ علاجياُ مستقلاُ.

## 4. المعمارية والمبادئ التقنية
- تفضيل تقنيات مفتوحة المصدر وقابلة للنقل.
- فصل الواجهة العامة عن التطبيقات الداخلية الحساسة.
- عزل نظام السجل الطبي عن المتجر والمنتدى والمحتوى العام، حتى لو استخدمت المنظومة هوية موحدة.
- تصميم API موثق لتسهيل التكامل واستبدال مزود الخدمة.
- PostgreSQL قاعدة بيانات مرشحة؛ ويُختار مزود الاستضافة بعد مقارنة التكلفة والأمان وقابلية النقل.
- GitHub لحفظ الكود والوثائق التقنية وإدارة الإصدارات.
- Notion لحفظ القرارات والمتطلبات وخطة الإنتاج وسجل التقدم.
- عدم تثبيت مزود استضافة أو خدمة مدفوعة قبل اختبار البدائل وموافقة صاحب المشروع.

## 5. الخصوصية والأمان — شروط غير قابلة للتجاوز
- يمنع وضع بيانات مرضى حقيقية أو صورهم أو تقاريرهم أو أرقام هوياتهم في مستودع GitHub أو صفحات عامة أو محادثات الوكلاء.
- التطوير والاختبار الأولي باستخدام بيانات اصطناعية فقط.
- فصل الصلاحيات حسب الدور ومبدأ أقل امتياز.
- تشفير النقل والتخزين، ونسخ احتياطية مشفرة، وسجل تدقيق، ومصادقة متعددة العوامل.
- لا يُفتح أرشيف المرضى للاستخدام الفعلي قبل مراجعة أمنية واختبار صلاحيات واستعادة النسخ الاحتياطية.
- تُراجع المتطلبات القانونية المحلية لحماية البيانات والتراخيص الطبية قبل التشغيل.

## 6. فريق الإنتاج متعدد الوكلاء
**صاحب المشروع:** د. رجب البربار — صاحب القرار النهائي واعتماد النطاق والهوية والنشر والإنفاق.

**ChatGPT — منسق الإنتاج:** يحافظ على هذه الوثيقة، ينسق المهام، يراجع الاتساق، ويقدم المقترحات والقرارات للاعتماد.

**وكلاء Claude المقترحون، عند إتاحة الربط:**
1. وكيل تحليل المنتج والمتطلبات.
2. وكيل هندسة النظام وقاعدة البيانات.
3. وكيل تجربة المستخدم والواجهة.
4. وكيل مراجعة الكود والاختبارات.

**وكلاء Z.ai المقترحون، بعد تهيئة API أو وسيلة الربط:**
1. وكيل البحث وجمع المصادر.
2. وكيل تصنيف المعرفة والمحتوى الطبي.
3. وكيل تحليل البيانات وضمان الجودة.
4. وكيل أتمتة سير العمل والتوثيق.

**قاعدة مهمة:** هذه أدوار مقترحة وليست دليلاُ على أن حسابات Claude أو Z.ai أو وكلاءها متصلة أو تعمل حالياُ. لا تُرسل مفاتيح API أو كلمات المرور إلى المستودع أو Notion أو ملفات المشروع. تُحفظ الأسرار في مدير أسرار آمن أو متغيرات بيئة خاصة.

## 7. بروتوكول العمل المشترك
1. كل مهمة تبدأ ببطاقة واضحة: الهدف، المدخلات، المخرجات، معايير القبول، والمخاطر.
2. الوكلاء يقدمون تحليلات أو فروع عمل أو Pull Requests؛ لا يدمجون تغييرات حساسة إلى الفرع الرئيسي دون مراجعة.
3. لا يغيّر أي وكيل قراراُ معتمداُ بصمت؛ يسجل التعارض ويطلب اعتماد صاحب المشروع.
4. تُسجل المصادر والافتراضات والنتائج غير المؤكدة.
5. لا نشر عام، ولا شراء، ولا مراسلة مرضى، ولا تعديل بيانات حقيقية دون موافقة صريحة.
6. تُراجع المخرجات الطبية من مختص بشري قبل نشرها.

## 8. مراحل التنفيذ المقترحة
- المرحلة 0: تثبيت المتطلبات، خريطة الموقع، الهوية، حالات الاستخدام، ومخطط البيانات.
- المرحلة 1: تصميم النظام والواجهة العامة ونظام التصميم.
- المرحلة 2: بناء الموقع الرئيسي وقسم العيادة والمحتوى التعريفي.
- المرحلة 3: المكتبة والفهرسة والمجلة الشهرية.
- المرحلة 4: المنظومة الداخلية ولوحة التحكم، ثم أرشيف المرضى المعزول بعد المراجعة الأمنية.
- المرحلة 5: المنتدى ومجتمع المرضى.
- المرحلة 6: التمريض المنزلي والحجوزات والإحالات.
- المرحلة 7: المتجر والتوريد بعد مراجعة الدفع والشحن والقواعد التنظيمية.
- المرحلة 8: الاستوديو الإعلامي والبرنامج الأسبوعي والأنيمي.
- المرحلة 9: تكاملات المنصات والوكلاء والأتمتة والتحليلات.

## 9. القرارات المفتوحة
- اعتماد لوحة الألوان النهائية والشعار والخطوط.
- اختيار اسم النطاق.
- تحديد أولويات إطلاق النسخة الأولى MVP.
- اعتماد التقنيات النهائية بعد اختبار البدائل المجانية.
- تحديد نطاق المجلة: فهرسة وتلخيص الأبحاث أولاُ، أم مجلة تستقبل أبحاثاُ أصلية وتحكّمها لاحقاُ.
- تحديد سياسة التسجيل والموافقة والخصوصية للمرضى والمنتدى.
- تهيئة تكاملات Claude وZ.ai والتحقق من حدودها وتكاليفها.
